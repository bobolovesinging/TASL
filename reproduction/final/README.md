# Final TASL implementation

This directory is the final learning/verification implementation used for the second revision. The preceding benchmark records and software remain available in `paper-v1`; they are not final-method reruns.

## Check the downloaded numerical evidence

```sh
python reproduce.py verify
```

This requires only Python and checks file hashes, all 40 five-seed learning runs, full-state pairing, all partition indices, numerical summaries, and storage/recovery accounting. It verifies recorded outputs; it does not claim to rerun training or verify unavailable tensor payloads.

## Recreate tensor payloads and rerun

Install the pinned dependencies with the PyTorch CUDA 12.1 wheel index. Training was run on RTX 3090 with PyTorch 2.5.1+cu121, torchvision 0.20.1+cu121, NumPy 1.26.4, and PyYAML 6.0.3. CKKS uses TenSEAL 0.3.16 in a separate environment. The recorded package list is included. No distributed DKG, IPFS service, or ledger service is supplied.

Use an empty workspace outside this release directory. The commands copy the executed sources there and leave the downloaded records untouched:

```sh
python reproduce.py c2 --workspace /path/to/fresh-run
python reproduce.py c1 --workspace /path/to/fresh-run
python reproduce.py c3-c6 --workspace /path/to/fresh-run --shard 0
python reproduce.py c3-c6 --workspace /path/to/fresh-run --shard 1
python reproduce.py c3-analysis --workspace /path/to/fresh-run
python reproduce.py c4 --workspace /path/to/fresh-run
python reproduce.py c7 --workspace /path/to/fresh-run
python reproduce.py feedback --workspace /path/to/fresh-run
python reproduce.py hbs --workspace /path/to/fresh-run
python reproduce.py plots --workspace /path/to/fresh-run
```

Run the two repeated-learning shards sequentially on one available GPU or with separate `CUDA_VISIBLE_DEVICES` values on two available GPUs. Avoid sharing a GPU with another workload. The repeated runner resumes only completed records whose source hashes match. Other suites intentionally refuse to overwrite an existing result directory. The first suite downloads Fashion-MNIST through torchvision. C2 creates the checkpoints and 50 bound input tensors needed by C3 analysis, C4, CKKS replay, and HBS. The two learning shards also create the five cap-study trajectories. Use the same workspace for dependent suites. LASA's unchanged three source files are fetched from the pinned author commit and checked by SHA-256; its licensing remains governed by the author repository. Its CUDA median requires deterministic warnings rather than a deterministic-kernel guarantee.

`summarize_results.py` and `plot_learning_curves.py` regenerate statistics/figures from a rerun's `results` directory. `python regenerate_tables.py` exports the five central numerical tables directly from the downloaded records to `analysis/central_tables.tex`, without training. `records/learning_curves.csv` contains the published 2,000 seed-round accuracy observations. Client-associated test allocations and per-class metrics are in `records/c3_analysis_v2`. Partition indices in `records/partitions` cover each of the 60,000 training examples exactly once for every seed and have been checked against executed loader hashes.

The frozen module docstrings retain some original prototype defaults. The explicit driver arguments and per-run manifests select the final configurations; `main.py` at repository root is an earlier entry point and is not used for these final comparisons. Every final run uses `compute_tasl_final_weights`, including the post-smoothing norm mask and pre-direction EMA history.

The released numerical records include full per-round weights, state hashes, configurations and inventory hashes. Large tensor checkpoints/captured updates are regenerated by the training commands rather than included in this download. Secret CKKS contexts are neither saved nor distributed. File sizes describe serialized bytes, not filesystem allocation or network replication. The HBS raw `duplicate_commit` rows are bookkeeping checks of recorded tuples, not an executed ledger service; they are excluded from every manuscript coverage count. Historical raw-output checks remain separate from final-version reproduction.
