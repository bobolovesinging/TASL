# Fifty-round HBS retention and TAS recovery

Fifty real Fashion-MNIST rounds, seed 42, ten clients, alpha 0.3,
40% label-flipping clients, 60,000 training samples and two local epochs.
The final fixed-participation governance configuration is retained; client
exclusion is disabled. A1/A2/A3 Executor attacks cycle over 17/17/16 rounds.
Two RTX 3090 GPUs run paired no-Executor and Full TAS captures.

HBS keeps all compact headers/governance, the five latest parent/input pairs,
and one current accepted W50 checkpoint. Older payloads are verified before
their active copies are removed. The flat checkpoint-and-prune backend
independently implements retention, sharing record bytes and the frozen TAS
worker so that the comparison isolates retention.

Each backend meets 550/550 expectations: 50 normal recoveries, 450 blocked
faults, and 50 no-archive controls (45 historical failures, five recent
successes). Fifty chained recoveries and fifty full-retention controls match
complete reference states. Verified checkpoint reads cover 31 warm-cache
samples per round. Active HBS bytes are 219,555,200 versus 2,039,961,654
for full retention, an 89.2373% reduction. Matched capacity is equal; with
one archive copy all policies retain 2,039,961,654 record/payload bytes.
Indexes are separate. Capture/output/verification copies are experiment tools,
excluded from the retention-policy inventory and preserved by the authors.

## Verify the published numerical evidence

Run `python verify.py` in this directory. It checks selected-file hashes,
1,200 raw-result JSON links, paired trajectories, retention totals and
recorded complete-state/read validation. It does not load binary states.

## Regenerate the binary capture and run disk verification

Measured environment: Python 3.10.21, PyTorch 2.5.1+cu121,
torchvision 0.20.1+cu121, NumPy 1.26.4, PyYAML 6.0.1,
matplotlib 3.10.6. Set TASL_DATA_ROOT to a FashionMNIST/raw cache.
In `code/hbs_recovery_loop_50round_20261012`, use fresh output directories:

```
export CUBLAS_WORKSPACE_CONFIG=:4096:8
export OMP_NUM_THREADS=4 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=4
python capture_fifty.py --group noexecutor --device cuda:0 --rounds 50
python capture_fifty.py --group trust_v1v2 --device cuda:1 --rounds 50
python capture_fifty.py --validate --rounds 50
python -c "import json; json.dump({'phase':'capture_complete'},open('job_status.json','w'))"
python -m unittest -v test_window test_storage_guards test_checkpoint_prune
python run_fifty_pipeline.py
python verify_fifty_results.py
```

The protocol-source hash is checked before recovery. Post-commit challenges
are drawn afresh and logged. Binary file hashes and timings depend on the
environment; compare complete states against each rerun's paired reference.
The large binary source snapshots, retained objects, recovered states and
a complete compressed archive remain in the authors' experiment archive.
They are regenerated by the commands above rather than included in this
selected public snapshot. Storage tables describe actual serialized bytes
at 50 rounds, distinct from the earlier aggregate-only extrapolation.

This is a local plaintext trusted-manifest experiment. It supports semantic
retention serving endorsed recovery, with no capacity advantage over the
same retention policy. It does not measure distributed ledger/IPFS service,
DKG, signatures, smart-contract gas or crash-atomic transactions. Fault cases
reuse one training trajectory rather than independent training replicates.
